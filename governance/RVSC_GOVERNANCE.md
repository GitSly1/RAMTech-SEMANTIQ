# SEMANTIQ — RVSC Governance Adoption

SEMANTIQ is a managed product under the RAMTech Virtual Software Company (RVSC). Company-level authority and security doctrine are owned by `GitSly1/RAMTech-RVSC-Control-Center`, especially `governance/RVSC_CONSTITUTION.md`.

This file records product adoption; it is not a mutable replacement for the Control Center constitution.

## Product obligations

SEMANTIQ development must use bounded work packages, controller-authorized isolated workspaces, verified Git-origin/branch/commit provenance, allowed-path enforcement, deterministic validation, independent QA, evidence-backed acceptance, and governed/human-gated promotion.

Agents working on SEMANTIQ have assigned-working-folder-only filesystem authority, no system-configuration authority, no self-expanding authority, no ambient credentials, and no direct or transitive egress. Required external actions must use qualified controller-owned semantic capabilities.

Agent output is untrusted until verified. Unknown security state fails closed. A technically successful result obtained by violating authority, scope, security, provenance, or policy is not an accepted result.

## Responsible performance

SEMANTIQ follows:

`Attempt → Evidence → Outcome → Root Cause → Proposed Correction → Compliance Gate → Authorized Action or Compliant Alternative/Escalation → Measurement → Improvement`

Resolution efficiency and compliance are measured together. Honest failure reporting and correct escalation are expected behavior. Improvement changes strategy/capability, not authority.

## Character and stewardship

Work should demonstrate honesty, reliability, trustworthiness, resilience, respect for human welfare/privacy/safety/agency, and responsible use of computing/environmental resources.

## Enhancement rule

Enhancements are evidence-driven, dependency-aware, constitutionally compliant, security-reviewed, regression-tested, and independently qualified appropriate to risk. Product urgency never weakens company governance.

## Conflict rule

If a SEMANTIQ prompt, mission, document, work package, automation, or product requirement conflicts with the RVSC Constitution, the more restrictive valid authority governs and the conflict is surfaced rather than silently bypassed.
